# Chromium: documented, not runnable here

The paper's Chromium column is not claimed by this artifact. Reasons, and what is recorded so the
experiment is reproducible in principle:

- A Chromium checkout is over a terabyte and a single instrumented build takes hours per
  configuration; no evaluator can be asked to do that, and it does not fit the container.
- The only Chromium build we have was made with an earlier compiler than the one shipped here, so
  it corresponds to no number this artifact claims.

What is recorded:

| Item | Value |
|---|---|
| Chromium revision | `bdef6783a05f0b3f885591e7d2c7b2aec1a89dea` |
| Build configuration | generated by the harness's `args.gn` (not shipped); per-configuration `BUILD.gn` variants add the `-mllvm` flags |
| Compiler flags | one build-flag line injecting the TSan compiler and the configuration's `-mllvm` flags (not shipped) |
| Telemetry changes | four upstream files with raised timeouts (the paper's numbers used them; not shipped) |
| Workload | Speedometer 3.1 and the Blink performance suites (`blink_perf.{parser,paint,image_decoder,svg}`), run through Telemetry with per-story repeats (5 for most stories, 10 for speedometer3, up to 20-50 for some layout and image stories) |
| CPU set | 16 to 48 pinned CPUs; a private Xvfb; Telemetry's browser-startup timeout raised from 60 s to 600 s |
| Known issue | `SierpinskiCarpet` in `blink_perf.svg` exceeds Telemetry's 10-minute per-story cap under ThreadSanitizer and is absent from instrumented rows |

The table above is what a reader would need to rebuild the experiment from a Chromium checkout at that
revision; budget days, not hours.
